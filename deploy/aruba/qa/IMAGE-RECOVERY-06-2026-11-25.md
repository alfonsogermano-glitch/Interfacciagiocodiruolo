# Native image recovery — image-recovery-06

## Scope and evidence

Production read-only audit confirms missing native references for 1 campaign
logo, 2 campaign covers, 1 character portrait and 8 narrative entities (2 NPCs,
6 monsters). Existing legacy image references are present, with no modern image
keys on these narrative entities.

Private bundle is generated by `deploy/aruba/scripts/build-image-recovery.py`.
Pillow is installed only in `.local/image-tools`, not the app runtime.
The builder verifies packaged file lengths/SHA256 and decodes every image
(including inline images). It normalizes image orientation and generates native
PNG assets and thumbnails, or bounded JPEG portrait/source binaries. Cropping/
rotation metadata is mapped to native narrative field names when present.

The resulting plan contains 12 entity/field associations and 17 visual assets,
plus the separate authenticated character portrait and portrait source. The
original export and source files remain unmodified.

## Safety boundaries

- No API/frontend deploy, schema/permission changes, bulk import or deletion of
  historical records. No old storage/network access.
- All entity/campaign identities and expected campaign owners are pinned.
- Original image references and crop metadata must still match source values.
- Modern image fields, portrait/source rows and branding references must be
  absent; even explicit modern null fields stop narrative recovery for review.
- All checks and writes execute in one transaction, under locks that exclude
  concurrent writes to affected tables. Existing new images stop the operation.
- Stored visual assets are same-campaign, authenticated native content URLs.
- Rollback only detaches references and restores original narrative payload
  keys if recovered fields still match. Later image changes stop rollback.
  Inserted visual assets remain to avoid breaking any new legitimate references.
- Original legacy fields are retained; source provenance is not overwritten.
- Private SQL contains image bytes: do not publish it or paste SQL error context.

## Verification performed locally

- Private source inventory verifies manifest integrity.
- Pillow decodes all selected historical image data during bundle generation.
- PGlite rehearsal with source-derived identity fixtures executes preflight,
  apply, exact binary/association verification, conditional rollback and retry
  guard. It checks 17 assets, 1 PG portrait, 1 logo and 2 campaign covers.
- A later user cover-image change makes rollback fail atomically: no portrait
  or campaign reference is partially reverted.
- Successful rollback reproduces every original narrative payload exactly.
- This is not an authenticated production browser render test.

Local rehearsal: `node .local/test-image-recovery.mjs` (private source required).

## VPS handoff

`recover-images.sh --preflight` checks expected production state read-only.
`--apply` takes a custom-format production backup, verifies the archive by a
complete restore to a restricted-connect clone, compares hashes/counts of the
affected tables and checks that production did not change during backup.
The clone rehearses apply/verify/rollback before production apply. Private logs
and backup paths are retained. No automatic restore over production occurs.

`--verify` checks exact stored binaries and references. `--rollback` backs up and
rehearses conditional rollback on a fresh clone before production rollback.
Database clone and backups are retained for deliberate later cleanup.

## 06b: migration 039 trigger compatibility

First production run stopped during the clone rollback comparison, before
production apply. The character table hash changed because native migration 039
touches `updated_at` and increments `revision` on portrait/source INSERT/DELETE.
The minimal initial local fixture had not included these triggers.

The corrected bundle is `hg-image-recovery-06b.tar.gz`. Backup restore comparison
remains full and unchanged. The separate rollback comparison excludes only
`updated_at` for the exact PG IDs receiving recovered portraits, and requires
exactly +4 revision increments (portrait/source INSERT + DELETE). All other
fields, records and tables remain compared. No trigger is disabled, no revision
is reset, and no general character-table comparison is skipped.

Local rehearsal now loads both actual migration 039 trigger functions. It
reproduces failure of the old full comparison and success of the constrained
comparison. An unrelated PG sheet edit still fails the constrained comparison.
Runner errors now identify the failing stage without printing private SQL.

Do not claim original context menu/editor parity or image restoration outside
the listed source records. Visible-copy changes remain a separate release.
